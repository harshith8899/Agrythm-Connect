| 1 Nov 2026 | Client: five call outcome flags drive what happens next. (1) Network drop: retry, attempt count does not go up. (2) Farmer asks for a specific time: call again at the requested time. (3) Farmer hangs up mid-call: retry, attempt count goes up by one. (4) Farmer refuses the information during the call: no retry, close the farmer for the day. (5) Successful call: done. |

| 1 Nov 2026 | Client confirmed the weather-missing retry as cumulative from the first failed check: check at +15 min, then +45 min, then +1 h 45 min; if still missing, skip with `weather_unavailable`. |
| 1 Nov 2026 | Client: if weather is missing, do not call. Retry the weather fetch 15 min later; if still missing, retry 30 min after that; if still missing, retry 1 hour after that; then skip the farmer and record `weather_unavailable`. |
| 1 Nov 2026 | Client: farmer data comes with consent, preferred language and details in the sheet. Only consent = Yes farmers are called. |
| 1 Nov 2026 | Calling and retries are done by Sarvam Campaigns (campaign mode is the production path). |

| 2 Nov 2026 | Team: the call no longer announces that the voice is an AI. The agent never claims to be human and answers honestly if a farmer sincerely asks. Calls are in local Hindi, local Kannada or English (Hindi first, then Kannada, then English), greet the farmer by name, give the weather for their village or district in the farmer's own language, ask if it was understood, and refuse everything outside the weather. Hindi and Kannada wording is a draft for native-speaker review. |
| 2 Nov 2026 | Weather facts spoken: temperature (low and high), wind speed, chance of rain and relative humidity, nothing else and no advice. Open-Meteo is asked for the 7-day forecast and every day is saved. If the provider fails or returns incomplete weather, retry after 15 min, then 30 min more, then 60 min more (`GATE0_WEATHER_RETRY_MINUTES`); if it still fails, the forecast saved on an earlier day for that date is used (ledger source ends in `-saved`). Only with nothing saved is the farmer skipped as `weather_unavailable`. The village/district lookup stays; the `weather-api` branch is not merged as a whole. During an outage the first place waits up to 1 h 45 min, other places in that run try once then use saved forecasts, so start the daily push early enough. |
| 3 Nov 2026 | Agent call flow changed. A first real call showed Sarvam plays the agent's own intro and ignores the opening-message override from the API, so the weather opening cannot be sent as text. New flow: the agent's intro greets the farmer by name, says it is Chetan Dabke's assistant and asks if it is a good time to talk; on yes the agent gives the weather itself from per-farmer variables (`farmer_name`, `place_name`, `temp_min_c`, `temp_max_c`, `wind_kmh`, `rain_chance_pct`, `humidity_pct`) and asks if it was understood. Campaign mode sends those variables per farmer. The one-farmer direct path cannot carry them yet, so it sends none (Sarvam returns 422 for an undeclared variable). |
| 3 Nov 2026 | The agent ends a call only after the farmer says they are clear, and always says the goodbye first. The maximum call length is 1500 s, the most Sarvam allows (a 90 s limit had cut a real call off while the farmer still had questions). It still never claims to be human. |
| 3 Nov 2026 | Agent output variables: `call_summary`, `callback_time`, `understood_weather`, `stop_calls_requested`. |
| 3 Nov 2026 | Telephony is an Exotel connection in Sarvam (Deploy, Phone numbers). Phone numbers, keys and IDs stay in `.env`, never in git. A Vobiz connection also exists with no number. The Exotel trial may only call verified numbers, so the first real test is to a team member's own phone. |
| 3 Nov 2026 | Client rule confirmed for requested-time callbacks: one attempt at the requested time, no retry if not picked up. Built only in the local test bench so far (not in git); the production job still has to implement it, together with a hosted scheduler. |
| 4 Nov 2026 | Telugu is supported as a fourth calling language (`Telugu` or `te` in the sheet; agent and script). Telugu wording is a draft until a native speaker reviews it. |
| 5 Nov 2026 | Callback conversation: when a farmer is busy or asks to be called later, the agent does not give the weather and does not comment on being busy. If the day or morning-or-evening is unclear (for example "tomorrow at 4", or "tomorrow" said late at night) it asks one short question that names the real date, then confirms the time in one sentence, says the normal goodbye (the usual closing greeting, unchanged) and ends. The agent may now say it will call at the confirmed time. `callback_time` is written as `HH:MM`, `tomorrow HH:MM` or `in N minutes/hours`. |
| 5 Nov 2026 | Calling window for callbacks: 5 in the morning to 10 at night (India time), set by the team. A farmer who asks for a time outside it is asked for a time inside it. Still to be confirmed with the client. |
| 5 Nov 2026 | The backend sends the agent a `now_text` variable (date and time in India) with every call, built by `script.format_now`; the agent uses it only to judge and confirm callback days. Agent version 8 and later declare it; an older version rejects it (HTTP 422). |
| 5 Nov 2026 | Call outcome rules (team, 5 Nov 2026): a connected call is a success only if the farmer said they understood the weather. A hang-up before that is a retry and counts as an attempt (3 attempts, 30 min then 1 hour). |
| 5 Nov 2026 | Call outcome rules: 'I don't need this' closes that farmer for the day with no retry; consent is unchanged and they are called again the next day. A clear 'stop calling me' on a second call, on a different day, stops the calls and tells a person, who updates consent. |
| 5 Nov 2026 | Call outcome rules: if the farmer only says hello, stays silent or cannot hear, the agent repeats the greeting once, then ends; the call counts as unanswered and is retried. |
| 5 Nov 2026 | Call outcome rules: a network drop gets up to 2 free retries a day (not counted as attempts); after that it counts as a normal attempt. A provider or number failure is retried once after 30 min, then marked failed and shown on the dashboard for the team. |
| 5 Nov 2026 | Callback rules: a farmer may move a callback at most 2 times. A callback may be placed up to 30 min late; after that it is marked missed and the message is sent instead. Consent and weather are checked again before the callback. |
| 5 Nov 2026 | Window and runs: if the calling window ends before the 3 attempts are done, calls stop, the day is 'unanswered' and the message is sent. If the backend was down for the daily run, it runs when it is back if still inside the calling window, otherwise the day is skipped and the team is alerted. |
| 5 Nov 2026 | Messages: WhatsApp first, SMS if the WhatsApp message cannot be delivered. Call consent covers messages about the call (to be confirmed with the client). The text is a fixed template with the four weather facts in the farmer's language, no free text from the call. Sent after a successful call, right after the last failed attempt (or an unanswered or missed callback). Declined, weather unavailable and skipped farmers get no message, only a dashboard alert for the team. |
| 5 Nov 2026 | Dashboard: the React dashboard on the `Dashboard` branch is the real dashboard and talks to the Python backend (`gate0/backend/weathercall/server.py`, built on `service.py`), not the earlier Node simulation. Same routes the dashboard already called, plus CSV farmer import and callbacks. Farmers, results and callbacks are stored in the backend's SQLite file for now (Supabase later). Google Sheets sync, the Apps Script write-back and the Trust AI analytics view were removed (Trust AI is out of scope for Gate Zero). "Send now" asks for confirmation when calls are real; the daily 9:00 auto-send is off until someone switches it on. |
| 5 Nov 2026 | Retries in the dashboard backend: a call that is not picked up, rejected (the phone network reports it the same way, as no answer), busy, or answered but not confirmed as understood is retried after 30 min, then after 1 hour (3 attempts); a provider or number failure is retried once after 30 min. No retry for a farmer who asked for a callback or to stop, none after 22:00 or on another day, and a retry the system missed by more than 30 min is dropped. The dashboard shows "Retrying" with the next try time, and "Unanswered" after the last attempt. Messages after the last attempt are not built yet. |
| 5 Nov 2026 | System Status tab: one page with connection checks (backend, database, Open-Meteo, Sarvam, phone line) and Sarvam usage (calls and billed minutes, counted from Sarvam's own call records the way Sarvam bills them: started 60-second minutes of connected calls, unanswered calls free). Sarvam has no API for the credit balance, so no balance or remaining credits are shown or estimated. An amount in rupees is shown as an estimate: billed minutes times a per-minute rate (default Rs 3.50, Sarvam pay-as-you-go, before GST; editable on the page for another plan). The exact figures and the balance are on Sarvam's Settings, Usage and Billing pages. An "insufficient quota" answer from Sarvam is flagged. Exotel bills its own minutes separately. |
| 5 Nov 2026 | Rules built in the dashboard backend after checking the code against the 5 Nov decisions: a callback can be moved twice, then no more (alert); 'stop calling me' on two different days stops that farmer's calls and alerts the team (a re-imported sheet row lifts the stop, since a person has then updated consent); a daily run that finds the backend back only after 22:00 is skipped with an alert, and one inside the window runs late; a provider failure with no retry left, and a farmer skipped for missing weather, raise a dashboard alert (`GET /api/alerts`, shown on System Status). Only the messages (WhatsApp, then SMS) are still not built. |
| 5 Nov 2026 | Team, replacing the earlier rows on 'I don't need this' and hello/silence: (1) 'I don't need this' is not retried that day and the farmer is called again the next day; if they say it again on another day the team is alerted, and calls stop only when the team sets consent to No. (2) Hello or silence: the agent repeats its greeting once, then ends; the call is shown as Unanswered and retried like a call not picked up. (3) Network drop: a connected call that Sarvam reports as ended by something other than the agent, the farmer or the time limit is retried after 5 minutes, twice a day, without counting as an attempt; a third drop counts as a normal attempt. Built with agent version 10 (`understood_weather` also takes `declined` and `no_response`); set `SARVAM_APP_VERSION=10`. The exact `ended_by` value Sarvam uses for a network drop is not documented and has not been seen yet, so any unusual end reason counts as a drop until a real one is checked. |
| 5 Nov 2026 | Farmer Directory: farmers from an import are kept in the database, and an admin can add a farmer by hand, edit any field, and switch a farmer active or inactive (an inactive farmer is skipped and shown as such). A phone number is never shown back in full: the edit form keeps the saved number when left blank. Consent is never assumed for a farmer added by hand: it is Yes only if the box is ticked. Re-importing a sheet replaces a farmer with the same Farmer ID, including the active flag and any edits. Dashboard layout: the filters are one row below the summary cards; the port badge, tab sub-titles and the 'Weather Voice Agent, Post-Call Monitoring' card were removed, since System Status shows connectivity. |
| 9 Nov 2026 | Dashboard: the Weather Advisories tab is removed. It read fields our backend does not send (so it was mostly empty), its 'advisory' wording promised advice the agent never gives, and the weather spoken to each farmer already shows in the call detail panel. Each farmer card has a Call button: with no result today it places the day's first call; with a retryable result (not picked up, not confirmed, failed) it places the next attempt now, the attempt count goes up by one and the waiting retry is replaced. It is refused, with the reason on the card, when the farmer is completed, declined, has a callback booked, has used all 3 attempts, is inactive, has no consent, asked to stop, or when it is outside 05:00 to 22:00. A confirmation always comes first. |
| 9 Nov 2026 | Call button, refined (product manager): pressing it asks, in a blurred in-dashboard box, which of two modes to use. (1) Follow the retry rules: the day's first call, or the next attempt (n of 3), as above. (2) Test call, ignoring the retry rules: a one-off call kept as its own Test row; it never changes the farmer's real result, attempt count, waiting retry, callbacks, stop or decline records or alerts, is left out of the summary cards, and can be repeated even when the day is completed. Both modes keep the hard rules: consent, active farmer, no stop request, 05:00 to 22:00. A test call places a real call when Sarvam is live. |
| 5 Nov 2026 | Hosting: the API on Render (Starter plan, one instance, Singapore) with its data in Supabase (Postgres, Mumbai), the dashboard on Cloudflare Pages, CI/CD on GitHub Actions (tests on every pull request; on `main` the dashboard deploys through the workflow and the API deploys on Render once checks pass). The browser never holds the token: a Cloudflare Pages Function forwards `/api/*` and adds it, and Cloudflare Access (team email login) must protect the Pages site. Steps in `docs/DEPLOY.md`. |
| 10 Nov 2026 | Hosting update: for the first 10 to 15 farmers the API runs on the Render free plan, kept usable by a wake-up timer in Supabase (pg_cron and pg_net, `gate0/supabase`, `docs/TRIGGER.md`). Every minute it asks whether a retry or callback is due within 3 minutes, whether today's send is due (auto-send on, from 08:57), or whether a send is under way, and if so calls the backend's `POST /api/tick`. The backend runs one pass at a time, so a wake-up never doubles a call and the calling logic is unchanged; a call 2 to 3 minutes late because of a cold start is accepted. Move to Render Starter (always on) for more farmers. |
| 10 Nov 2026 | Lost calls are recovered: a retry or callback is marked with the time it was taken; if it is still 'calling' after 10 minutes the backend stopped mid-call (a restart or crash). Each pass first looks that call up at Sarvam (last 4 digits of the number and the time) and, if found, saves its result as normal, with any callback time counted from when the call ended; if not found it drops the claim and alerts the team, and never dials again on a guess. Found when a real second attempt asking for 09:35 was lost to a restart. Also: the overview opens on Today (summary and list), the conversation shows what was said in the call's own language with the English summary on top (the guessed 'English script' and 'Translate' views are gone), and System Status says whether the backend runs on Render (service and version) or on a computer, and shows the Supabase wake-up timer. |

| 10 Nov 2026 | Weather source on hosting is WeatherAPI.com (free key `WEATHERAPI_KEY`; with it set the backend uses it, otherwise Open-Meteo as before). Places are looked up once, when a farmer is added or imported. |
| 14 Nov 2026 | The wake-up timer starts waking the backend for the daily send at 08:47 (was 08:57) and pings it every minute until the send has run, so the free plan's 15-minute idle sleep cannot catch it before 09:00. Retries and callbacks still wake it 3 minutes early. The sign-in page wakes the server as soon as it opens and never gives up; Sign in waits for the server and signs in the moment it is up, and a Cloudflare Worker with no BACKEND_URL or API_TOKEN is reported at once instead of looking like a slow start. |
